Status bar alternatives to custom_barista

A1 report, 2026-11-17. Machine: Arch, i3-wm 4.25.1 on X11, sway 1.12 installed, PipeWire 1.6 (pulse shim), RTX 5070 Ti, AMD CPU (k10temp). Repo state: 8fc269c. Upstream numbers were collected from the GitHub/Codeberg/Arch APIs on 2026-11-17.

1. Executive summary

Recommendation: migrate to i3status-rust, in stages. Run it next to the current bar for a week, then switch. This repo stays as a fallback and holds the two scripts we still need (ccusage, clipboard). It takes about half a day.

Why:

  1. barista is dead upstream. soumya92/barista has been archived since 2024-06-25. Its last commit was "Rehome project to github, remove references to barista.run, cleanup for archiving". The vanity domain has expired: https://barista.run/?go-get=1 now redirects (301) to expireddomains.com. We still build only because proxy.golang.org caches our pinned barista.run v0.0.0-20240418001405-c936f35316af. The final upstream commit declares a new module path, github.com/soumya92/barista. The only fork with recent commits, barista-run/barista, has 0 stars and 3 commits (2026-06-23).
  2. The breakages are in code we own. The GPU bug (int to float) and the hwmon bug were in our own parsing (nvidia/nvidia.go, temp/hwmon.go). i3status-rust ships these as built-in blocks (nvidia_gpu, temperature via libsensors, cpu frequency, sound with a PipeWire driver). After an upgrade, many users report and fix such breakages upstream. It is active: v0.40.1 on 2026-11-08, about 3.2k stars, already in Arch extra.
  3. Icons (high weight). i3status-rust has per-block icon sets built in (icons = "material-nf", or awesome4..7, emoji). Every block gets a fitting glyph without hand-picking, and you can override any of them by name.
  4. It works on sway too. The same config feeds swaybar, so a later move to sway or Wayland costs nothing extra.

Icon root cause found in our code, worth fixing either way. The GPU widget does ask for icons: pango.Icon("mdi-thermometer") and "mdi-memory" in nvidia/nvidia.go:67,69. But main.go never loads the mdi provider, and barista quietly returns an empty node for an unknown provider (barista pango/icon.go:34-48). The same happens in vol/vol.go:18,30, which uses ion-* although no ionicons provider exists. typicons is loaded but no widget uses it. If we keep barista, loading mdi fixes the "no GPU icon" problem in minutes and gives 7,447 icons instead of Material's 932.

When to stay on barista instead: if you value the per-core frequency histogram (freq/) and full Go control over the bar more than having upstream maintain the widgets. In that case do the "keep" plan in section 8, about 2 hours.

7. Per-alternative cards

Keep barista status quo

  • Covers everything, full Go control (freq histogram, compact layout), no migration
  • Low resources (26 MB RSS, one process)
  • Upstream archived, the vanity domain expired, and we depend on the Go proxy cache
  • We fix every format change ourselves (nvidia-smi, hwmon, /proc)
  • Icons are hand-picked; two widgets render blank icons today

i3status-rust recommended

  • Built-in blocks for 11 of our 13 widgets, including nvidia_gpu, libsensors temperature, PipeWire sound
  • Preset material-nf icons for every block and state; 19 themes
  • Very active (release 9 days ago), in Arch extra, also works with swaybar
  • Custom block: JSON output, interval, signal, watch_files, clicks
  • TOML plus a format DSL instead of code. The per-core freq histogram becomes a script or $frequency
  • Upstream format changes between minor versions (0.x) can need config edits

py3status

  • Large module set (nvidia_smi, sysdata, volume_status, net_rate, xkb_input); Python modules are easy to write
  • Active, in Arch extra
  • Python runtime, wraps i3status for some data; no icon sets

bumblebee-status

  • Modules for nvidiagpu, sensors2, pipewire, layout-xkb; icon themes
  • Python; last release 2025-07; AUR only

i3blocks + scripts

  • Simplest model, any language
  • Every widget is our script, so the same maintenance burden as now, without barista's helpers. Upstream last released in 2019

i3status

  • Tiny, stable C, already installed
  • No GPU, freq, layout, clicks or custom modules: a non-starter alone

polybar

  • Rich X11 bar, ramps, clicks and scroll, many fonts
  • Replaces i3bar entirely (restyle from scratch); last release 2024-08; no Wayland path

yambar

  • Very light C, X11 and Wayland
  • Few system modules (temp, GPU, freq are scripts); last release 2024-04; AUR

sway + waybar

  • Active, CSS theming, temp via hwmon-path-abs, wireplumber, tooltips
  • Means changing the compositor (sway 1.12 is installed): NVIDIA and Wayland, i3 config port, X11-only tools (xclip, xgb kbdlayout). A large move for a bar problem

eww / ags / ironbar

  • Widget frameworks: popups, graphs, anything
  • Most effort and most code to maintain; ags/ironbar are Wayland-only; eww's last release was 2024-04

8. Migration sketches

A. i3status-rust (recommended), about 4-5 h

  1. pacman -S i3status-rust ttf-nerd-fonts-symbols (5 min).
  2. Write ~/.config/i3status-rust/config.toml (sketch below, check the keys against the block docs) (1.5 h).
  3. Scripts: ccusage.sh prints i3status-rs JSON {"text","state","icon"} from ccusage blocks --active --json | jq, at interval = 30 with a pinned version (see risk R3). clip.sh prints the clipboard size. Both can live in this repo under scripts/ (1 h).
  4. Side by side: add a second bar { status_command i3status-rs ...; font pango:PragmataPro, Symbols Nerd Font 10 } block to the i3 config for a week. Then remove the barista bar (0.5 h, plus tuning widths and colors, 1 h).
  5. Rewrite CLAUDE.md/README: the repo becomes "bar config + scripts". The "Widget health" recurring check turns into "i3status-rs config still valid after upgrade".

B. Keep barista, hardened, about 2 h

  1. Icons (15 min): clone MaterialDesign-Webfont to ~/.fonts/mdi, call mdi.Load(utils.Home(".fonts/mdi")) in main.go, and give GPU and volume real names (mdi-expansion-card, mdi-volume-high). Drop the unused typicons, and later move the remaining material-* names to mdi-* so one font remains. Add a startup check that logs any pango.Icon name that resolves to nothing.
  2. Module path (30 min): rewrite the imports in 20 files from barista.run/... to github.com/soumya92/barista/... at v0.0.0-20240625171803-069b4f375d00, the final commit, which declares that path. A replace line probably fails on the path mismatch. Alternatively, vendor (go mod vendor) so that the build does not depend on a dead domain.
  3. ccusage (20 min): npx ccusage@latest every 5 s means a Node start every 5 s and an unpinned package fetched from npm. Pin the version and poll every 30-60 s.
  4. Clipboard (10 min): reading the whole clipboard with xclip -o every 2 s just to get its size is wasteful. Poll less often, or use xclip -t TARGETS first.
  5. Upgrade resilience (30 min): parser table tests for hwmon and freq, like the new nvidia_test.go, and short error reasons in every widget.

  2. Module path or vendor (B2), folded into the queued "Dependency survey" item.

  4. Run the "Widget health sweep" (queued #3) and add parser tests for hwmon and freq (B5).
