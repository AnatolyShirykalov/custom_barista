# Custom Status Bar

An i3 status bar built on [i3status-rust](https://github.com/greshake/i3status-rust): two bars (`bar-main` on DP-0, which always owns the tray, and `bar-small` on DP-2), a few custom script blocks and a Win+i toggle. (An earlier Go bar on barista.run was removed 2026-11-18; see git history.)

## Contents

- `config.toml` - block config (icons `material-nf`, colors from the scheme below), bar on DP-0
- `compact.toml` - generated by `scripts/gen-compact.sh` for the smaller DP-2 (no disk space/IO, Claude usage, IP); edit config.toml and rerun
- `scripts/` - custom blocks and helpers:
  - `freq.sh`, `gpu.sh` - CPU frequency and GPU blocks
  - `reboot-needed.sh` - hidden unless a reboot (kernel replaced / boot package upgraded) or relogin (session package) is due; package lists at the top of the script; `list` argument names the packages (hover, left click notification)
  - `claude-usage.sh` (Claude usage block; prices in `claude-prices.json`) and `claude-rl-tap.sh` (rate-limit tap feeding it); they replace the old `ccusage.sh`
  - `explain.sh <key>` - prints the explanation text of a block (text only; used by hover)
  - `hover-tee.py` - `status_command` pass-through that taps the status line and clicks for the daemon; `hover-daemon.py` - the tooltip daemon; `hover-run.sh` - its supervisor (single instance, restarts after a crash, log `hover.log`)
  - `hover/` - daemon modules `layout.py`, `state.py`, `rundir.py`, and `keys.toml` (block -> explain key); tests in `test_hover.py`
  - `barsconf.sh` generates `bars.conf` from `i3/bars.conf.tmpl`; `barcycle.sh` toggles the bars; `gen-compact.sh` generates `compact.toml`
- `install.sh` - applies the setup (see Install); `i3/bars.conf.tmpl` - template of the i3 `bar {}` blocks
- `scripts/test.sh` - script tests (fixtures in `testdata/`)

### Color scheme

- `good`: #6d6 (green) - normal
- `degraded`: #dd6 (yellow) - warning
- `bad`: #d66 (red) - critical
- `dim-icon`: #777 (gray) - icons

## Install

`sudo pacman -S i3status-rust ttf-nerd-fonts-symbols-mono`, then `./install.sh [--dry-run] [--no-restart] [--yes]` from the checkout (any location), as the user who runs the bar. Idempotent: pulls the repo (`--ff-only`, skipped if dirty), warns about missing tools, generates `~/.config/custom_barista/{config,compact}.toml` (tracked files stay untouched), writes the bar blocks to `~/.i3/bars.conf` (`scripts/barsconf.sh` from `i3/bars.conf.tmpl`, keeps the current Win+i state; paths in `~/.config/custom_barista/bars.env`) and an `include` of it, the `$mod+i` binding and the hover `exec_always` between `# BEGIN custom_barista` / `# END custom_barista` in `~/.config/i3/config.local` (`scripts/i3block.sh`: created if missing, other lines kept, a symlink is written through and stays a link; paths as `~`). `~/.i3/config` is managed elsewhere (setup repo) and never written: it must end with `include ~/.config/i3/config.local`; an old custom_barista block or `bar {}` blocks there are only warned about. Old files are backed up (`config.local.bak-<date-time>`, `bars.conf.bak-<date-time>`), the whole config is checked with `i3 -C -c ~/.i3/config` (restored on failure, exit 1) and i3 is restarted. `--yes` is accepted but nothing asks any more. A saved state `barista` from the old Go bar is treated as `rs`.

Runtime deps (`install.sh` warns about missing ones): `i3status-rs`, a Nerd symbols font; used by blocks and click actions `jq`, `curl`, `flock`, `nvidia-smi`, `xdotool`, `pavucontrol`; for hover tooltips `python-xlib` and `python-gobject` (GTK 3, Pango); optional `yad` (calendar popup); `~/scripts/open_calender.sh` (not in this repo).

## Hover tooltips

i3bar has no tooltips, so `hover-daemon.py` (started by `hover-run.sh` via i3 `exec_always`) shows one: hover a block for 500 ms to see its explanation, then slide to another block to switch. `scripts/hover/keys.toml` maps blocks to `explain.sh` keys (edit it when adding a block). Turn it off with `HOVER=0 ./install.sh --yes`; the setting persists in `bars.env`, so Win+i keeps it. Middle-click popups were removed 2026-11-20. Log: `hover.log` in `$XDG_RUNTIME_DIR/custom_barista/hover` (else a private `/tmp/custom_barista-$UID/hover`).

## Win+i

Toggles off <-> i3status-rust. `barcycle.sh` rewrites `bars.conf` for the next state (both bars switch `mode` and `status_command`), checks `i3 -C` (restores on failure) and runs `i3-msg reload`; the state survives an i3 restart. The tray never moves to another i3bar process (that lost icons); presses are serialized with a lock. If a bar ever freezes after very fast switching, `i3-msg restart` recovers it.
