# Custom Barista Status Bar

A custom status bar implementation for i3 window manager based on [barista](https://github.com/soumya92/barista), featuring system monitoring modules with modern styling.

> Note: upstream barista.run is archived (see [docs/design/A1-alternatives/report.html](docs/design/A1-alternatives/report.html)). This repo also carries a trial i3status-rust bar, see below.

## Modules

In the order wired in `main.go`:

- `kbdlayout` - keyboard layout indicator
- `load` - system load average
- `temp` - CPU/hwmon temperature sensors
- `freq` - CPU frequency
- `mem` - memory usage
- `dsk` - disk space
- `nvidia` - NVIDIA GPU temperature and VRAM (via `nvidia-smi`)
- `netm` - network interfaces with traffic stats
- `batt` - battery level and charging state
- `vol` - audio volume
- `ccusage` - Claude Code usage (tokens, remaining time)
- `clipboard` - clipboard contents
- `ltime` - time and date (always last)

Icons come from the Material Design and Typicons fonts.

## Installation

### Prerequisites

- Go 1.23 or later (see `go.mod`)
- i3 window manager
- X11 environment
- Material Design and Typicons fonts (`fonts/`, see Font Setup); `nvidia-smi` for the GPU module

### Install

```bash
go install github.com/AnatolyShirykalov/custom_barista@latest
```

### Font Setup

Copy the included fonts to your fonts directory:

```bash
cp -r fonts/* ~/.fonts/
fc-cache -fv
```

## Configuration

### i3 Configuration

Add to your `~/.i3/config` or `~/.config/i3/config`:

```
bar {
    position bottom
    status_command exec $GOPATH/bin/custom_barista
    font pango:PragmataPro Mono 11
    colors {
        background #2f2f2f
        statusline #ffffff
        separator #666666
    }
}
```

### Color Scheme

The bar uses a custom color scheme:
- `good`: #6d6 (green) - Normal/good status
- `degraded`: #dd6 (yellow) - Warning status  
- `bad`: #d66 (red) - Critical status
- `dim-icon`: #777 (gray) - Inactive icons

## Apply the setup for another user: install.sh

`./install.sh [--dry-run] [--no-restart] [--yes]` from the checkout (any location), as the user who runs the bar. Idempotent: pulls the repo (`--ff-only`, skipped if dirty), warns about missing tools, runs `go install .`, generates `~/.config/custom_barista/{config,compact}.toml` (tracked files stay untouched) writes the bar blocks to `bars.conf` next to the i3 config (`i3status-rust/scripts/barsconf.sh` from `i3status-rust/i3/bars.conf.tmpl`, keeps the current Win+i state; paths in `~/.config/custom_barista/bars.env`) and an `include` of it plus the `$mod+i` binding between `# BEGIN custom_barista` / `# END custom_barista`. Old `bar {}` blocks are shown and removed only on `y`. The config is backed up (`config.bak-<date-time>`, `bars.conf.bak-<date-time>`), checked with `i3 -C` (restored on failure) and i3 is restarted. Needs beforehand: go, i3status-rs, the fonts (see above) and `~/scripts/clipboard_menu.sh`, `open_calender.sh` (not in this repo).

## Trial bar: i3status-rust

A second bar, for comparison during a trial week. Config and scripts live in `i3status-rust/`.

Install: `sudo pacman -S i3status-rust ttf-nerd-fonts-symbols-mono`

Runtime deps (same list `install.sh` warns about): required `go`, `i3status-rs`, fonts; used by blocks and click actions `jq`, `xclip`, `node`/`npx` (ccusage), `nvidia-smi`, `xdotool`, `pavucontrol`; optional `yad` (calendar/clipboard popups).

- `i3status-rust/config.toml` - block config (icons `material-nf`, colors from the scheme above), bar on DP-0
- `i3status-rust/compact.toml` - generated by `scripts/gen-compact.sh` for the smaller DP-2 (no disk space/IO, ccusage, IP); edit config.toml and rerun
- `i3status-rust/scripts/` - custom blocks: `freq.sh`, `ccusage.sh`, `clip.sh`, `gpu.sh`; `barcycle.sh` switches bars
- `i3status-rust/scripts/test.sh` - script tests (fixtures in `testdata/`)

i3 config: generated by `install.sh` (see above): `bars.conf` holds the three bars `bar-barista`, `bar-rs` (DP-0), `bar-rs-small` (DP-2).

Win+i cycles: off -> barista -> i3status-rust (both rs bars) -> off. `barcycle.sh` rewrites `bars.conf` for the next state (visible bar docks and holds the tray on DP-0, others invisible with `tray_output none`), checks `i3 -C` (restores on failure) and runs `i3-msg reload`; the state survives an i3 restart.

## Building from Source

```bash
git clone https://github.com/AnatolyShirykalov/custom_barista.git
cd custom_barista
go build -o custom_barista
```
